# gf 鈫?Rust port map

Goal: a pure Rust implementation of GoFrame, package for package, in this repository.

- Reference (read-only): `D:\github\gf`, module `github.com/gogf/gf/v2`, version `v2.10.5`.
- Target: this repository (`gf-rust`), a Cargo workspace whose package paths mirror the Go ones.
- Measured plan: [`whole-app.md`](whole-app.md), generated by
  `rust-anything analyze D:\github\gf --whole-app`. It lists all 320 units, the
  waves, and the dependency decisions D1-D91.

Scope: the whole framework 鈥?core module first, then `cmd/gf`, then `contrib/*`
(see [ADR-002](DECISIONS.md#adr-002-scope-is-the-whole-framework-in-base-first-order)).

## Open questions

1. Go is installed (`go1.25.0`); the `cgo` bridge lane works with
   `CGO_ENABLED=1` and `C:\msys64\mingw64\bin` on `PATH` (see `HANDOFF.md`).
   The translated-test lane (ADR-008) stays the default because it is faster
   than a round trip per unit.
2. External dependency crates (D2-D89): OpenTelemetry, Polaris, Nacos, Consul,
   etcd, ZooKeeper, K8s, database drivers, TUI libraries. To be researched per
   topic in `research/` before the units that need them.
3. `util/gconv` and `container/*` semantics depend on the final `Value`
   contract (numeric widening, string coercion, map key casing, struct
   representation). Freeze it in an ADR before wave 8.
4. `gf-json` still delegates float encoding to `serde_json`, whose exponent
   spelling (`1e300`) differs from Go's (`1e+300`); fix it with the
   `format_g` helper when the JSON unit is revisited (ADR-037).
5. `os/gmutex` is gated as a unit but nothing uses it yet; `garray` and
   `gmap` keep their own locks (ADR-007), so there is no rewrite planned.
6. `util/gvalid` has no struct-tag lane (ADR-039). Decide between a
   `#[derive(Validate)]`-style macro emitting `Rules::Map` and a
   `Validatable` trait implemented by hand; the HTTP unit will force the
   choice, because Go's request validation reads tags from the struct.
7. `gregex::match_string` drops empty trailing capture groups where Go's
   `FindStringSubmatch` keeps them; `gvalid::parse_tag_value` works around it.
   Fix the helper (and its tests) or keep the documented divergence.
8. Error creation is slower than Go only because of stack capture:
   `Backtrace::force_capture` is 964 ns vs `runtime.Callers` 265 ns, while the
   rest of `Error::new` is 63 ns; rendering is 1.87x faster
   ([BENCH.md](BENCH.md)). Revisit a bounded capture in a new ADR only if
   creation ever shows up in profiles.
